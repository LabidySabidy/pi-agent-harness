# Cross-Project Lessons

> Patterns that apply across projects. Loaded at session start alongside the project-specific LESSONS.md.
> Promote items here via `/skill:gardening`.

## Danger zones

- GL-001 [anchor] Windows path encoding — Backslashes in file paths break in multiple contexts: JSON strings need `\\`, `file://` URLs need forward slashes, grep patterns need escaping. Always test path construction on Windows before assuming it's portable. **Sub-note (silent no-op):** a substitution or grep that matches nothing still exits 0 — and the JSON layer carrying these paths eats one backslash level *before* your pattern runs, so `\\` in a tool call arrives as `\`. A search for `C:\\Users\\…` therefore finds nothing while reporting success, and a "successful" redaction can be a no-op. Verify the OUTPUT (grep the result), never the exit code. **Sub-note (process rule):** on Windows, ad-hoc shell E2E is where these traps concentrate — heredocs eat backslashes, each shell/tool layer eats another, and MSYS converts POSIX paths in env vars but *not* inside embedded JSON strings, so a path can arrive as `C:\Users\…` in one place and `/tmp/…` in another within the same command. Write the E2E as a **script file** and run it; never inline it in the shell. Four recurrences in one session were all inline-shell artifacts, and false failures from them look exactly like real bugs.
- GL-002 `gh` CLI not installed — Projects with `branch_tracking: true` depend on `gh` for PR creation. The branch-hygiene skill detects this at Phase B step 0, but projects without branch tracking won't catch it until the first PR is needed. Check `gh auth status` early.

## Gotchas

- GL-003 Pi `edit` tool whitespace sensitivity — The `oldText` must match exactly including line endings. Windows CRLF vs LF differences cause silent failures. When an edit fails to find text, check line endings first.
- GL-004 `git branch --merged` includes current branch — The `*` prefix on the current branch line is not a grep-friendly marker. Parse output by dropping lines starting with `*` and the base branch name, rather than grepping.

## Decisions made

- GL-005 Skills over monolithic prompts — Pi harness uses composable skills with `/skill:name` invocation rather than one large system prompt. Each skill owns one workflow. Skills reference each other explicitly (e.g., plan-then-implement → grill, plan-then-implement → branch).
- GL-006 AGENTS.md frontmatter over new config files — Project-level configuration (e.g., `branch_tracking: true`) lives in project AGENTS.md as YAML frontmatter. No `.agent/config` file. This keeps the convention count low and the config visible.

## Anti-patterns

- GL-007 Don't jam new features into existing skills — plan-then-implement should not absorb branch creation, approach exploration, or review workflows. Each concern gets its own skill. Skills reference each other at integration points (one-line invocations), not by merging text.
- GL-008 Don't create a new config file when AGENTS.md frontmatter works — Same pattern as above. Frontmatter is machine-parseable, human-readable, and already loaded at session start. Adding `.agent/config` creates a second convention with no benefit.

## Always do

- GL-009 Verify before claiming — Per AGENTS.md verification-before-claim rule: never claim "done," "fixed," or "passing" without fresh verification output in the current message. "Tests pass" is not verification; the test output in the message is. "Grepped for keywords" is not verification; the matched line with line number is. The `Verified:` line in every recap must cite specific evidence. This applies across every project, every session.
- GL-010 Branch before code — When `branch_tracking: true`, the first non-trivial Write/Edit on main must be preceded by `/skill:branch` Phase A. Session-start protocol item 3 checks this.

- GL-013 [anchor] Extension changes verify only in a fresh session — Pi loads extensions at session start; code written this session is not the code running this session. Verification = restart, then read back the artifact (stats file, telemetry line, config) in the new session. A checkbox without a post-restart read-back is a claim, not a verification.
- GL-014 [anchor] Voluntary model-emitted protocols are not persistence — If durable state depends on the model remembering to emit a tag/tool call, it fails silently. Drive durable writes from framework hooks (session start/end, turn end); treat model-emitted signals as best-effort enrichment with an observable, logged miss.
- GL-015 Before proposing to link, vendor, or copy code into a global install path, check whether that path is already inside a version-controlled repo (`git -C <dir> rev-parse --show-toplevel`; `git ls-files <path>`). If it is, the install path IS the source — there is nothing to link. Linking/junctions are only warranted when the install path is outside version control. Sub-note: a Windows junction is a validated escape hatch if that ever changes — `readdirSync(withFileTypes)` reports it as `isSymbolicLink: true`, and pi's loader accepts `isSymbolicLink()` for both files and directories (`loader.js:584,592`).
  - Related harness facts: extensions live in `agent/extensions/` of the `pi-agent-harness` repo; tests sit next to the source and run with `node --test "agent/extensions/**/*.test.ts"` (Node 24 strips types; `~/.pi` has no package.json). Keep pure logic in pi-free modules so it is testable without the extension runtime — `telemetry/buckets.ts` is the precedent.
  - Discovery detail worth knowing: pi resolves `extensions/<dir>/` only via `index.ts`, `index.js`, or a package.json `pi.extensions` manifest. Other files in that subdirectory are ignored, so a module directory with no entry point is inert.
- GL-016 Never `.slice()` or single-char-regex (`.`) over emoji — BMP and astral glyphs differ in UTF-16 width. ⬜ (U+2B1C) is 1 unit; 🟥🟨🟩🟦 are 2. Slicing corrupts the astral four and can write an unpaired surrogate into SCHEMA.md. Capture the glyph with a regex group.
- GL-017 Never import a package's internal file by subpath — a modern `exports` map throws `ERR_PACKAGE_PATH_NOT_EXPORTED` for undeclared subpaths, and ESM-only packages expose no `require` condition. Resolve the package root first (`import.meta.resolve` when `require.resolve` fails), then import the target by absolute `file://` URL. Hit twice in this project's history: `process-bridge.ts` resolving the bundled pi CLI, and a throwaway verifier importing the extension loader.
- GL-018 Hook cardinality — `turn_end` fires per **agent turn**, and one user prompt spans several when tools run; `agent_end` fires once per **run**. Use `agent_end` for once-per-run semantics (recording a gap, emitting a summary, incrementing a counter). Getting this wrong is not subtle: it produced three `telemetry_missing` events for a single grill turn, and a `turns: 4` count for a one-line exchange. Related: if a field is meant to count user exchanges, count user messages — never derive it from turn events.
- GL-020 [anchor] Hard-killing a server ORPHANS ITS CHILD PROCESSES — `taskkill /PID <pid> /F` without `/T` kills the parent and skips its signal handlers, so any child it spawned keeps running. For a server that supervises an agent, that means **killing the server leaks the agent**: the child holds the working directory, keeps a model session open, and survives every subsequent "I stopped the server" check. Always `taskkill /PID <pid> /T /F` to take the tree, and prefer a graceful stop so the parent's own cleanup runs. Two further traps from the same afternoon: killing "the process listening on the port" only kills **listeners** (a process that failed to bind, or that was superseded, stays alive silently and accumulates), and a stale listener makes a healthy port look occupied by the current build. Before trusting an end-to-end result, enumerate by command line — `Get-CimInstance Win32_Process | Where-Object CommandLine -match '<pattern>'` — not by port, and kill the whole tree.
- GL-021 An unexplained count has a mechanical cause — When a number is larger or stranger than reality, do not explain it as "probably test data". Reproduce it, enumerate the inputs, and find the duplication. Two examples: a "10 courses" that was one fixture copied by a test plus a leftover registry entry, and a "10th course" that was the same directory reached twice by scan and by `PROJECT_DIR`, deduped into `<name>-2`. Both were dedupe artifacts, not mysteries, and both were found by displaying the input set rather than inferring it.
- GL-022 [anchor] Verification must name the artifact it observed — A stale server or a cached bundle yields a **plausible result from the wrong code**, which is the most dangerous class of false pass because nothing looks broken: the response is well-formed, the page renders, the numbers are simply from the previous build. Read the identity of what actually served or ran it — bundle hash, process cwd and pid, response headers — and state that identity as part of the evidence. Never assume the deployed artifact is the observed one. Bit twice in one project: a detached server from a previous session holding the port while `/health` answered `ok`, and a browser executing `index-<oldhash>.js` after a rebuild because `index.html` was cacheable. **SPA variant:** opening the URL a single-page app is *already on* is a no-op — no navigation fires, so React keeps its previous state and a failure path can appear to succeed because the previous success is still on screen. Force a remount (navigate elsewhere first, or reload) before verifying a branch you have already exercised. **Browser-input variants, both stale-state observation:** setting `input.value` directly does NOT fire React's `onChange` (React tracks the previous value; use the native setter — `Object.getOwnPropertyDescriptor(HTMLInputElement.prototype, "value").set.call(input, v)` then dispatch `input`), and reading the DOM synchronously after `click()` reads the **previous** render because React updates asynchronously — await a tick. Both produced convincing false product bugs: a slider that "did not respond" and a game launch that "produced no outcome". **Third variant, and the most expensive: reading a PROXY for the state, or the wrong element once the DOM grows.** A `disabled` attribute was read as "busy" for two sessions and produced a filed defect (`T-051`) with a plausible mechanism and a wrong fix direction, entirely disproved by instrumenting the server: the button's own LABEL read `Send`, i.e. not busy — an empty textarea disables Send in every chat UI. Meanwhile `querySelector(".prose")` kept returning the FIRST match, so "prose frozen at 1396 characters" was turn 1's message being re-read while turn 2 rendered into the second element. **Read the property that MEANS the state (a label, a count, a server-side line), select by last-match or by count when a list grows, and when a defect resists two sessions of reasoning, INSTRUMENT THE BRANCH rather than reasoning harder** — the log killed it in one run.
- GL-023 Destructive cleanup is driven by the IGNORE RULES, never by directory NAMES — A directory name is not a runtime artifact. `SESSIONS/`, `ASSETS/`, `cache/` and their like collide with committed content that happens to share the name, so `find . -name SESSIONS -exec rm -rf {} +` deletes authored files as readily as generated ones. Delete what the ignore rules say is untracked (`git clean -Xdn` to preview, `git clean -Xdf` to act; `git check-ignore -v <path>` to confirm a specific path), or delete an explicit path list. Applied case: an over-broad `find -name SESSIONS` removed a committed fixture directory; it was recovered with `git checkout`, but it would have been silent if the change had already been committed.
- GL-024 [anchor] A parser that silently drops on mismatch turns a formatting variation into a MISSING FEATURE — If a pattern does not match, say so. Three instances in one project, each discovered only because a user noticed a feature that could not have worked: a hardcoded 88-dash table separator (any dash-count change silently skipped every row insert), a `[a-z]+` capture group for module types (every hyphenated type — `course-challenge`, `primary-source`, `ai-activity` — was rejected, so those types could never have loaded), and a field regex requiring indentation (an unindented `- **cites:**` was ignored, so specs failed with "missing citation" rather than "unrecognised field"). **Rule: parse permissively, accept a range of shapes, and WARN on anything unrecognised — never silently succeed.** Silent success is the bug; a warning is the fix. Related: a guard is not a guard until it has been seen to fail — inject a violation, watch it go red, then revert. **The fourth face of the same failure mode: a BARE `catch {}` that lets the caller report success.** A `try { doWork() } catch { /* ignore */ }` around code that then returns "ok" converts a thrown error into a silent no-op — the caller logs a success line that is simply untrue. Applied case: a notification fan-out referenced a variable an earlier edit had deleted, threw `ReferenceError`, swallowed it, and the watcher logged a successful re-parse while sending nothing to any client. Either log the error, or re-throw, or return a failure — never let an empty catch sit upstream of a success report.
- GL-026 [anchor] Switching branches in the harness IS deploying — The install path IS the working tree (GL-015), so `git checkout` silently **installs or uninstalls extensions for every project's pi session**. Creating a branch and committing there removes those files from the tree pi loads; the feature stops existing the moment you switch away, and nothing warns you. Never leave the harness on a branch you are not deploying: merge the PR, or keep the change on the shipped branch and work elsewhere. Applied case: a new global extension was built, verified, opened as a PR — and then `git checkout main` deleted it from the working tree, so the "already live" claim was true only while the branch was checked out.
  - **Sub-note, and the reason this was not caught: an aggregate test count proves nothing about which files loaded.** `node --test a.test.ts b.test.ts` where `b.test.ts` does not exist reports only `a`'s tests and **exits 0** — a green number that silently excludes the exact thing just built. It reads as "41 pass" when 35 ran. **Mechanical guard: `node run-extension-tests.mjs` from the harness root.** Every test file is declared explicitly; a declared file that is missing REFUSES the run, an undeclared `*.test.ts` on disk REFUSES the run, and each file is run separately with its own count printed and asserted against a floor. Never invoke `node --test` on a path list by hand, and never with a glob — a glob matches only what exists.
- GL-025 [anchor] A rewrite can silently drop behaviour an earlier phase verified — When a component or view is replaced, every acceptance criterion the OLD implementation satisfied becomes unverified, not still-satisfied. Re-run the earlier phases' criteria against the new implementation before marking the later phase done. Applied case: a hot-reload criterion ("SCHEMA.md change hot-updates badges without reload") was verified in an early phase, then a frontend rewrite removed the consumer of the reload event while the criterion stayed green for four phases — the watcher fired and the server re-parsed the whole time, and nothing reached the UI. The criterion's checkbox was never revisited because nothing about it *looked* broken.
- GL-019 Runtime logs are not documentation — absolute paths leak the OS username — Any log that records `cwd` or file paths embeds the OS username, so treat it as a private runtime artifact: gitignore it in every repo hosting that data and commit only the path-free source-of-truth files. Applied case: a **public** repo ignored `.agent/telemetry*` but not `.agent/learning/events.jsonl` or `.agent/learning/SESSIONS/`, leaving the log one `git add .` from publication. Nothing had been pushed, so the fix was a gitignore and no history rewrite — scrubbing after a push would not have removed it from history.
- GL-027 [anchor] ANY file directly in `agent/extensions/` that exports no factory BREAKS EVERY PI SESSION — pi auto-discovers `~/.pi/agent/extensions/*.ts` as GLOBAL extensions and loads each one; a file with no factory makes pi refuse to start (`Error: Failed to load extension "…": Extension does not export a valid factory function`). The mechanism is **placement + missing export**, not the filename: the first instance was `bash-quiet.test.ts`, and the next will be a stray helper .ts dropped there while thinking of it as a module. The failure is total and cross-project, and it *looks like anything but a placement mistake* — every consumer of pi reports its own error three layers away (socrates-web's tutor showed `{"error":"pi process exited"}`), so debugging starts in the wrong repo. Reproduce the spawn by hand in the same directory before debugging the caller: `pi -p "hi"` printed the real error immediately. Guards: `run-extension-tests.mjs` REFUSES on any direct `*.ts` here that has no `export`, and on any `*.test.ts` regardless (keep those in `tests/`). Second-order trap the same incident exposed: a guard can be green and still not cover the failure — the file was declared, present, and passing while breaking startup, because nothing asserted *where* it lived or *what it lacked*; the rule is now stated on the property that breaks pi, not on the example that did.
- GL-028 [anchor] Measure an optimization's NET effect, not its gross saving — An optimization's benefit is visible and its cost is not. `bash-quiet` and `read-cache` were both deleted after **replaying recorded sessions through their own decision logic** — re-run the pure function over every recorded `tool_result`, with no model in the loop, so it is deterministic and takes seconds instead of hours. Across 38.8 h of socrates-web: bash-quiet collapsed 72 outputs (median 4 lines; 37 of them ≤4 lines, so the `✓ passed · N lines · full: <path>` stub was often LONGER than the output it replaced), and the model re-read the stashed temp file after **75%** of collapses, refetching **109%** of the hidden content. Net **−2,271 tokens** before counting the read-back commands, which alone cost 19,277. Its >200-line path fired **zero** times, because the model already pipes its own output through `| head -N` and never emits 200 lines. `read-cache` had **2** exact repeat reads in the same span. The trap: the *fix* to bash-quiet looked like a +12,164-token win while the mechanism it fixed was net-negative — **a tweak that improves a mechanism is not evidence the mechanism should exist.** Corollaries: (1) a mechanism that HIDES content will be chased — measure how often something fetches it back, and treat that as its cost; (2) count OPPORTUNITIES, not successes — an extension firing 72× in one session and 0× in the next 25 h is idle, not working; (3) replaying a log is the cheapest instrument available and replaces a 13.8 h feedback loop with a 5 s one. Second-order finding from the same audit: the real cost centre was **thinking** (29% and 56% of context across the two sessions) — a layer no extension touched, while all the effort went to the 13–16% bash layer. Measure which layer dominates *before* optimizing inside one.
- GL-029 [anchor] A hand-maintained test-file LIST fails SILENTLY when it goes stale, and a GLOB that matches nothing is the same failure in another shape — Either way the run is green, the counts look plausible, and the file nobody named is never executed. Three observed instances in one project (socrates-web), each found only by looking for it: (1) `web/package.json` ran `node --test src/ui.test.ts`, a hardcoded name, so a newly added client test file was **silently excluded** and its assertions never ran; (2) the root script names 11 files by hand and had already gone stale — `web/src/*.test.ts` was absent from it, running only because the command happened to chain the client suite; (3) `node --test "src/**/*.nonexistent.ts"` matched nothing and **exited 0** with `pass` printed, which is indistinguishable from a passing suite. The same class as the GL-026 sub-note (a file that does not exist is not reported by `node --test`), generalised: the runner cannot verify its own completeness, so the check must be a SEPARATE step. **Fixes, both cheap and both now in place:** glob the file list (`node --test "src/**/*.test.ts"`) so a new file is picked up by construction, AND run an independent coverage check that enumerates `*.test.ts` on disk and refuses if any is unreachable from the scripts — run it FIRST, before the tests, or a stale list produces a green run of an incomplete suite. Also worth doing what the harness does: run each file SEPARATELY and print its own count, because an aggregate total proves nothing about which files ran, and assert a non-zero count per file so a file that stops discovering tests is visible rather than counted as a pass. A guard is not a guard until it has been SEEN TO FAIL: prove it by adding an unnamed file, by reverting to a hardcoded name, and by pointing the glob at a non-existent path — all three must refuse.
- GL-030 [anchor] An observable that is ABSENT cannot distinguish "did nothing" from "never ran" — and a diagnostic is worthless if nobody checked where its output goes — Chasing a failing feature, the only observable was a log entry that never appeared, read as "the code is not running". It was wrong in both directions: the code WAS running (a downstream side effect proved it), and the real fault was in the write path, not the read path. Three mechanical failures made that possible, each cheap to avoid. (1) **A silent early return hid a delivered-but-ignored event.** `apply()` short-circuited on `next === live` before its only `appendEntry`, and because the caller wrote the level FIRST, that branch was the normal path — so a working feature and a broken one produced identical evidence. Never let the success path and the not-run path share one observable; log the decision, not just the transition. (2) **Diagnostics were added to code whose module instance could not be confirmed.** Every failure branch of the helper was instrumented, none fired, and the conclusion drawn was "not executing" — but the emit and the test were separated by a dev-server module cache (extension factories are memoized per path, and Turbopack caches aggressively), so the instrumented code may simply never have been the code serving the request. Editing a file is not deploying it; establish that the running artifact contains the change (GL-022) BEFORE trusting a negative result from instrumentation. (3) **A log file was trusted because it was RECENT, not because it was known to receive the output.** `.next/dev/logs/next-development.log` was live and current — it carried server lines — so it was read as authoritative, and `console.log` from the changed module may never have gone there at all. Recency is not connectivity. Verify the channel with a deliberate marker BEFORE relying on the channel's silence. The generalisation: a NEGATIVE observation is only as strong as the weakest link in the chain that would have produced a positive one, so whenever "it did not happen" is the evidence, first prove the detector can see it happen.
- GL-031 [anchor] A TRUNCATED READ IS NOT A READ, and a grep of ONE VERSION is not a check of the system — Told the user a package "cannot run on pi at all" and cited two real checks: `docs/usage.md:306` ("it intentionally does not include built-in MCP") and a `grep -rli mcp` over the **global 0.80.3 CLI**, which found nothing. The conclusion was still false. The package ships a first-class Pi installer — `pi install npm:context-mode`, `~/.pi/agent/mcp.json`, and an extension hooking `tool_call` / `tool_result` / `session_start` / `session_before_compact`, the same events this harness's own extensions hook. The evidence was in the source I had already fetched and **had not finished reading**: 30K of a 92K-char page, with the Pi section starting at ~60K. Two mechanical errors compounded. (1) **A partial read treated as a complete one.** A paginated fetch states its own limits ("Showing 29891 of 91864 chars"); a section that has not been reached yet is not a section that does not exist. When a fetch reports a range, the read is unfinished by construction — finish it before drawing any negative. (2) **A version-scoped check reported as a system-wide fact.** Two pi installs live here (0.80.3 global CLI, 0.84.3 bundled with pi-web) and only the newer reads `mcp.json`. The grep answered for 0.80.3 and I said "pi". Every capability check must name the version it checked, because a stale binary answering confidently is indistinguishable from a correct answer until someone acts on it. The tell was available and ignored: the user said the package came from **pi.dev**, the vendor's own site, which makes "not built for pi" a claim needing positive evidence rather than a default from an empty grep. Corrected only because the user pushed back on their own recollection — the cheapest detector is to notice when a NEGATIVE about someone's own tooling contradicts their direct experience of where they got it. Related: GL-030 (an absent observable cannot distinguish "did nothing" from "never ran") — here the missing section was read as "does not exist" when it was simply "not fetched yet".
